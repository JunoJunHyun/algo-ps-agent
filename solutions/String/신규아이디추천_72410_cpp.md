## 1. 굿노트 설계 요약
- 1~7단계 문자열 변환 과정을 정규표현식 치환(regex_replace)과 기본 STL 함수(tolower, empty, substr, back) 조합으로 단순화하여 설계함.
- 핵심 정규표현식 메타문자([], [^], ^[], []$, +)를 별도로 정리하고, 2단계([^a-z0-9-_.]), 3단계(\.+), 4단계(^[.]|[.]$), 6-2단계([.]$)에 대응하는 패턴을 단계별로 매핑함.
- 5페이지 초기 손코딩 이후 6~9페이지에 걸쳐 정규표현식 풀이를 4회 반복 백지 복습하며 패턴 및 <regex> 헤더 구문을 점검함.

## 2. 필기 vs 실제 코드 오차 분석 (Gap Analysis)
- 제어문 블록 범위 차이: 손필기(5~6페이지)에서는 6단계 if(answer.size() > 15) 내부에 substr(0, 15)와 끝 마침표 제거(regex_replace)를 중괄호({})로 묶었으나, 실제 통과 코드에서는 중괄호가 생략되어 길이가 15 이하인 경우에도 끝 마침표 제거가 항상 실행되도록 작성됨.
- 정규표현식 메타문자 및 이스케이프 누락: 백지 복습(6~9페이지) 과정에서 C++ 문자열 내 백슬래시 이중 이스케이프(\.+) 누락( .+ 또는  .+), 4단계 OR 연산자(|) 누락(^[.] [.]$), 2단계 대괄호([]) 누락 및 오기(^a-20-9--.) 등이 발생했으나 최종 코드에서 정확히 교정됨.
- C++ 문법 및 로직 오기 수정: 손필기에서 헤더 닫는 꺾쇠 누락(#include <regex), 세미콜론 누락, 대소문자 오기(String, Solution), 9페이지 7단계의 잘못된 대입식(= answer.popback())이 나타났으나 통과 코드에서 표준 C++ 문법(answer += answer.back())으로 수정됨.

## 3. C++ 실전 개선 팁
- C++ std::regex는 객체 생성 비용이 크고 실행 속도가 느린 편이므로, 문자열 길이가 길거나 시간 제한이 엄격한 실전 코테에서는 손필기 3-1처럼 STL 순회(isalnum, substr, pop_back 등)로 구현하는 것이 유리함.
- 정규표현식 패턴 내 백슬래시 이중 이스케이프(\\.)가 헷갈릴 경우 C++11 Raw String Literal(예: R"(\.+)")을 사용하면 이스케이프 오타를 줄일 수 있음.
- if문 아래에 두 줄 이상의 로직을 작성할 때는 의도치 않은 제어 흐름 버그를 방지하기 위해 반드시 중괄호({})를 명시하는 습관을 권장함.

## 4. 최종 통과 코드 (C++)
```cpp
#include <iostream> 
#include <string>
#include <vector>
#include <cstring>
#include <regex>

using namespace std;

string solution(string new_id) {
    string answer = "";
    //1
    for(char& ch : new_id)
        ch = tolower(ch);
    //2
    answer = regex_replace(new_id, regex("[^a-z0-9-_.]"), "");
    //3
    answer = regex_replace(answer, regex("\\.+"), ".");
    //4
    answer = regex_replace(answer, regex("^[.]|[.]$"), "");
    //5
    if(answer.empty())
        answer = "a";
    //6
    if(answer.size() > 15)
        answer = answer.substr(0, 15);
        answer = regex_replace(answer, regex("[.]$"), "");
    //7
    while(answer.size() < 3)
        answer += answer.back();
    return answer;
}
```
